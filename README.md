# 하우스헌팅

전세와 매매 후보를 금액, 입주일, 장단점, 별점으로 비교하고 내 예산에 맞는지 계산하는 한 페이지 앱.
Cloudflare Worker에 올리면 구글이나 이메일로 로그인하고, 사람마다 자기 장부만 봅니다.

`index.html` 한 파일이 앱 전부입니다. 시작할 때 `/api/me`를 두드려 보고 서버에 붙습니다.
서버가 없으면 브라우저 저장으로 내려가므로 파일만 열어도 동작은 합니다.

---

## 지금 배포된 곳

**https://house.myoung.world**

| 항목 | 상태 |
|---|---|
| Worker | 배포됨 |
| 주소 | `house.myoung.world` 로 붙임 (wrangler.toml 의 `routes`) |
| D1 `house-hunt` | 만들어짐, 표 9개와 뷰 하나 적용 |
| 세션 열쇠 | secret 으로 등록됨 |
| 구글 로그인 | 켜짐 (`GOOGLE_CLIENT_ID`·`GOOGLE_CLIENT_SECRET` 등록됨) |
| 가입 코드 | 안 씀 — 이메일 가입은 초대 링크로만 열립니다 |
| 관리 화면 | 켜짐 (`ADMIN_EMAIL` 등록됨) |
| 장부 함께 쓰기 | 적용됨 (migrations/001) |
| 구글·연령대 | 적용됨 (migrations/003) |
| 연령대 통계 | 적용됨 (migrations/004) |
| 사진 | 됨 (D1에 담김) |
| R2 사진 저장소 | 안 켬 — 선택 사항 |
| 매일 백업 | GitHub Actions 로 돎 |

### 사진은 어디에 담기나

R2 버킷이 연결돼 있으면 거기에, 없으면 D1에 담습니다. 지금은 D1 쪽으로 돕니다.
앱이 알아서 한 장을 긴 변 1280px로 줄여 올리고, 그래도 크면 화질을 낮춥니다.

| | R2 있을 때 | 지금 (D1) |
|---|---|---|
| 한 장 크기 | 6MB | 700KB |
| 장부당 장수 | 제한 없음 | 300장 |
| 줄이는 크기 | 긴 변 1600px | 긴 변 1280px |

임장 사진 몇십 장이면 D1으로 충분합니다. 더 많이 쌓을 생각이면 대시보드에서
R2를 켠 뒤 `wrangler.toml`의 `[[r2_buckets]]` 세 줄 주석을 풀고 아래를 실행하세요.
이미 올린 사진은 D1에 그대로 남고, 새 사진부터 R2로 갑니다.

```bash
npx wrangler r2 bucket create house-hunt-photos
npx wrangler deploy
```

가입 코드를 바꾸려면 이 한 줄이면 됩니다. 다시 배포할 필요는 없습니다.

```bash
npx wrangler secret put SIGNUP_CODE
```

## 배포 순서

### 1. D1 만들기

```bash
npx wrangler d1 create house-hunt
```

출력에 나온 `database_id`를 `wrangler.toml`에 붙여넣은 뒤 테이블을 만듭니다.

```bash
npx wrangler d1 execute house-hunt --remote --file=schema.sql
```

### 2. 사진 저장소 만들기

```bash
npx wrangler r2 bucket create house-hunt-photos
```

사진을 안 쓸 거면 건너뛰고 `wrangler.toml`의 `[[r2_buckets]]` 블록을 지우세요.

### 3. 비밀값 넣기

꼭 있어야 하는 건 세션 열쇠 하나입니다.

```bash
openssl rand -base64 48
npx wrangler secret put SESSION_SECRET
```

세션 서명용 열쇠입니다. 위에서 나온 값을 붙여넣으세요. 이게 없으면 로그인이 아예 안 됩니다.

**구글로 로그인하게 하려면** 구글 클라우드 콘솔에서 OAuth 클라이언트(웹 애플리케이션)를 만들고, 승인된 리디렉션 URI 에 `https://<주소>/auth/google/callback` 을 넣은 뒤 두 값을 등록합니다. 둘 중 하나라도 없으면 구글 단추가 화면에서 사라지고 이메일 로그인만 남습니다.

```bash
npx wrangler secret put GOOGLE_CLIENT_ID
npx wrangler secret put GOOGLE_CLIENT_SECRET
```

**이메일로도 새로 가입하게 하려면** 가입 코드를 넣습니다. 안 넣으면 이메일 가입은 초대 링크로만 열립니다.

```bash
npx wrangler secret put SIGNUP_CODE
```

**관리 화면을 쓰려면** 내 이메일을 넣습니다. 자세한 건 아래 [관리 화면](#관리-화면)에 있습니다.

```bash
npx wrangler secret put ADMIN_EMAIL
```

### 4. 배포

```bash
npx wrangler deploy
```

주소가 나오면 끝입니다. 열면 로그인 화면이 뜹니다.

## 같이 쓸 사람 들이기

들어오는 길이 둘입니다.

**구글로** — 주소만 알려주면 됩니다. 구글로 계속하기를 누르면 계정과 자기 장부가 생깁니다. 초대 없이 시작할 수 있지만, 남의 장부는 초대를 받아야 봅니다.

**이메일로** — 초대 링크로만 들어옵니다. 설정 화면의 함께 쓰는 사람에서 링크를 만들어 보내면, 받은 사람은 가입을 마치고 그 장부로 바로 들어옵니다. 아래 [장부를 함께 쓰기](#장부를-함께-쓰기)에 있습니다.

초대 없이도 이메일로 가입하게 하고 싶으면 가입 코드를 넣습니다. 코드는 카톡으로 보내도 됩니다. 코드로는 자기 계정을 만들 수 있을 뿐, 남의 매물은 못 봅니다.

```bash
npx wrangler secret put SIGNUP_CODE
```

**다 들어오고 나면 코드를 지우세요.** 지우면 이메일 가입은 다시 초대 링크로만 열립니다.

```bash
npx wrangler secret delete SIGNUP_CODE
```

**이메일까지 못 박고 싶으면** `wrangler.toml`에 한 줄 더 씁니다. 구글이든 이메일이든 이 목록에 없으면 들어오지 못합니다.

```toml
ALLOWED_EMAILS = "나@gmail.com,배우자@gmail.com"
```

## 구글로 로그인하기

구글로 계속하기를 누르면 구글에 다녀온 뒤 계정이 생기거나 기존 계정으로 들어갑니다. 이 계정에는 비밀번호가 없습니다.

**같은 이메일의 비밀번호 계정이 이미 있으면 한 계정으로 합쳐집니다.** 그 뒤로는 구글로도, 비밀번호로도 들어올 수 있습니다. 구글이 이메일 확인을 마친 계정만 합칩니다.

**사람은 이메일이 아니라 구글이 주는 고유 번호로 알아봅니다.** 구글 계정의 이메일을 바꿔도 같은 사람으로 남고, 남이 그 이메일을 새로 받아도 이 사람의 장부에는 못 들어옵니다.

**처음 들어온 사람에게는 연령대를 한 번 묻습니다.** 안 밝혀도 됩니다. 아래 [연령대와 통계](#연령대와-통계)에 있습니다.

구글 쪽에서 어긋나면 로그인 화면으로 돌아오며 이유를 보여줍니다. 흔한 것은 이메일 확인이 안 끝난 구글 계정, 로그인을 중간에 그만둔 경우, 창을 오래 두어 시간을 넘긴 경우입니다.

| 막는 것 | 어떻게 |
|---|---|
| 남이 지어낸 로그인 응답 | 구글에 보내기 전에 만든 임의값을 서명한 쿠키에 담아 두고, 돌아온 값과 맞춰 봄 |
| 다른 앱에 발급된 정보 | 구글이 준 정보의 발급처와 대상이 이 앱인지 확인 |
| 한 구글 계정이 여러 이메일에 붙는 것 | 고유 번호에 유일 제약 |
| 무더기 가입 | 아이피당 한 시간에 5번 |

## 비밀번호를 잊었을 때

비밀번호는 서버에 없어서 찾아줄 수 없습니다. 임시 비밀번호로 갈아끼웁니다.

```bash
node tools/reset-password.mjs 배우자@gmail.com "임시비밀번호1234"
```

출력된 SQL을 실행하면 그 사람의 기존 로그인이 전부 끊기고 임시 비밀번호만 통합니다.
알려준 뒤 앱의 설정 화면에서 본인이 바꾸게 하세요.

---

## 비밀번호를 어떻게 지키는가

구글로만 들어온 계정에는 비밀번호가 없습니다. 이 절은 이메일 계정 이야기입니다.

**비밀번호는 서버에 도착하지 않습니다.** 브라우저가 PBKDF2로 60만 번 늘린 결과만 보냅니다. 워커는 거기에 임의 소금을 섞어 1만 2천 번 더 늘려 저장합니다. D1을 통째로 훔쳐도 원래 비밀번호를 캐려면 한 번 찍을 때마다 61만 번을 돌려야 합니다.

늘리는 일을 브라우저에 맡긴 이유는 Workers 무료 플랜의 요청당 CPU 한도 때문입니다. 61만 번을 워커에서 다 돌리면 한도를 넘깁니다.

**대신 서버가 비밀번호 길이를 검사하지 못합니다.** 비밀번호를 못 보기 때문입니다. 10자 제한은 화면에서 겁니다. 온라인으로 찍어보는 공격은 아래 횟수 제한이 막습니다.

| 막는 것 | 어떻게 |
|---|---|
| 무차별 대입 | 이메일당 15분에 8번, 아이피당 24번 실패하면 15분 잠금 |
| 가입 남용 | 아이피당 한 시간에 5번 |
| 계정 있는지 떠보기 | 없는 계정에도, 구글 전용이라 비밀번호가 없는 계정에도 같은 계산 시간과 같은 문구 |
| 세션 위조 | HMAC 서명, HttpOnly, SameSite=Lax, 30일 만료 |
| 비밀번호 바뀐 뒤 남은 세션 | 계정마다 세대 번호를 올려 전부 끊음 |
| 다른 사이트에서 보낸 요청 | 쓰기 요청은 Origin 검사 |
| 스크립트 주입 | 페이지마다 nonce를 새로 발급하는 CSP |
| 프레임에 끼워 넣기 | `frame-ancestors 'none'` |

## 장부를 함께 쓰기

데이터는 **장부(book)** 단위로 묶입니다. 가입하면 자기 이름을 딴 장부가 하나 생기고, 거기에 다른 사람을 불러들일 수 있습니다.

**부르는 쪽** 설정 화면의 함께 쓰는 사람에서 초대 링크를 만들어 보냅니다. 링크는 7일 동안 살아 있고 한 번 쓰면 닫힙니다. 언제든 끌 수 있습니다. **가입 코드는 따로 안 보내도 됩니다.**

**받는 쪽** 링크 하나만 열면 끝입니다. 계정이 없으면 가입 화면이 뜨는데, 초대로 들어온 것이라 가입 코드를 묻지 않고 어느 장부에 초대됐는지 알려줍니다. 가입을 마치면 그대로 그 장부에 들어옵니다.

가입 코드는 **자기 장부를 새로 만드는 사람**에게만 필요합니다. 그때는 코드를 링크에 담아 보낼 수 있습니다.

```
https://house-hunt.<계정>.workers.dev/auth/signup?code=<가입코드>
```

**들어온 뒤** 두 사람이 같은 매물 목록을 함께 보고 적습니다. 한 장부에 6명까지 들어올 수 있습니다.

| 할 수 있는 일 | 주인 | 참여자 |
|---|---|---|
| 매물 적기·고치기·지우기 | O | O |
| 장부 이름 바꾸기 | O | O |
| 초대 링크 만들기·끄기 | O | X |
| 참여자 내보내기 | O | X |
| 장부에서 나가기 | X | O |

**별점만 사람마다 따로 매겨집니다.** 둘이 같은 집을 보고 각자 점수를 주면 서로 덮어쓰지 않고 나란히 남습니다. 표의 총점은 매긴 사람들의 평균입니다. 입력 폼에서는 내 점수를 매기고, 상대가 준 점수가 옆에 작게 보입니다.

여러 장부에 속하면 머리말에 장부 고르기 상자가 생깁니다.

## 네이버부동산에서 가져오기

매물 추가 화면 맨 위에 **네이버부동산에서 가져오기** 상자가 있습니다. 네이버부동산 매물 상세 화면을 전체 선택해 복사한 뒤 붙여넣으면 아래 칸들이 저절로 채워집니다. 붙여넣는 순간 바로 채우고, 무엇을 채웠는지 아래에 적어 줍니다.

| 읽어 오는 것 | 네이버 쪽 라벨 |
|---|---|
| 이름 | 단지명, 없으면 맨 윗줄에서 거래 형태 앞부분. 뒤에 층을 붙여 같은 동 매물끼리 구분합니다 |
| 거래 형태 · 보증금 · 매매가 | 매매가 / 전세가 / 보증금, 없으면 맨 윗줄 |
| 관리비, 포함 항목 | 관리비 (원 단위를 만원으로 바꿉니다. `5만 5,000원` → 5.5) |
| 전용 면적 | 전용면적. `공급/전용면적 114㎡/85㎡` 은 차례를 보고 전용 쪽을, `공급34㎡ (전용28.55)` 는 괄호 안을 고릅니다 |
| 층, 주차 | 해당층/총층/주차대수, 주차가능여부 |
| 방, 욕실 | 방수/욕실수 |
| 향 | 향, 방향 (`(안방 기준) 남향` 처럼 괄호가 붙어도 됩니다) |
| 입주 가능일, 현 세입자 | 입주가능일. `2027년 08월 14일` 도, `즉시입주`(공실)도, `협의`(모름)도 읽습니다 |
| 주소 | 소재지, 또는 시도로 시작하는 줄 |
| 가까운 역, 도보 | 000역 도보 0분 |
| 매물 링크 | 매물번호로 주소를 되살립니다 |
| 기타 메모 | 매물 설명 문구, 월세, 기전세금, 융자금, 대지지분, 방구조, 준공연도 |

설명 문구는 확인매물 날짜 바로 위에 있습니다. 그 자리에 `집주인` 같은 꼬리표가 끼어 있으면 위로 세 줄까지 거슬러 올라가 찾습니다.

**빈 칸만 채웁니다.** 이미 적어 둔 값은 그대로 두고, 무엇을 건너뛰었는지 알려 줍니다. 거래 형태처럼 고르는 칸만 덮어씁니다.

**여러 매물을 한꺼번에 복사했다면** 맨 앞의 한 건만 채우고 몇 건이 붙었는지 알려 줍니다. 나머지는 매물별로 다시 붙여넣으면 됩니다.

네이버가 표시하는 평당가는 공급면적 기준이고, 이 앱의 평당가는 전용면적 기준이라 숫자가 다릅니다.

**URL을 붙여넣어 자동으로 긁어오지는 않습니다.** 네이버가 브라우저 밖에서 오는 요청을 차단해 두었습니다. 서버에서 매물 API를 부르면 첫 요청부터 `TOO_MANY_REQUESTS` 가 돌아오고, 브라우저에서 직접 부르는 길은 CORS 가 막습니다. 복사해서 붙여넣는 쪽이 막히지 않고 이용약관에도 걸리지 않습니다.

## 예산

예산 탭에 가진 돈과 버는 돈을 넣으면 매매와 전세로 얼마까지 볼 수 있는지 계산합니다.

**돈은 별점처럼 사람마다 따로 적고 합쳐집니다.** 현금, 주식, 청약, 그 밖의 자산, 월 실수령, 갚는 빚까지 참여자마다 블록이 하나씩 생깁니다. 각자 자기 것만 채우면 되고 서로 덮어쓰지 않습니다. 블록 오른쪽에 그 사람의 순자산이, 아래에 합계가 나옵니다.

**혼자 쓰면 이름 없이 한 덩어리로 보입니다.** 판 제목도 "내 돈"으로 바뀌고 합계 줄은 나오지 않습니다.

전세보증금, 지원받을 돈, 남겨둘 돈, 생활비, 저축처럼 누구 하나의 것이 아닌 항목은 공용 칸에 한 번만 적습니다.

계산은 세 단계입니다.

1. **매달 낼 수 있는 돈** — 합산 소득에서 생활비·저축·기존 대출 상환을 뺀 값과, 소득 대비 상환 한도(기본 40%) 중 작은 쪽
2. **빌릴 수 있는 돈** — 그 월 상환액으로 원리금균등 역산한 금액과, 집값 대비 대출 한도(기본 70%)로 정한 금액 중 작은 쪽
3. **적정 상한** — 내 돈과 대출을 합친 뒤 취득세·중개보수(기본 2.5%)를 덜어낸 값. 전세는 이자만 내므로 따로 계산합니다

표와 카드와 비교 화면에 매물마다 **여유 / 빠듯 / 예산 밖 / 현금으로** 배지가 붙고, 월에 얼마가 드는지 같이 보입니다. 예산 열을 누르면 그 기준으로 정렬됩니다.

직접 넣은 숫자로만 계산합니다. 실제 대출 한도와 금리, 세금은 은행과 세무서가 정합니다. 규제는 자주 바뀌므로 한도 값은 모두 직접 바꿀 수 있게 열어뒀습니다.

## 남의 장부가 안 보이는 이유

모든 행이 `book_id`를 달고 있고, 워커는 요청할 때마다 **이 사람이 이 장부의 참여자인가**를 먼저 확인한 뒤 그 장부의 id로만 질의합니다. 남의 장부는 SQL 단계에서 안 걸립니다.

`properties`의 기본키가 `(book_id, id)`라 다른 장부가 같은 매물 id를 써도 서로 안 덮입니다.

사진은 `/photo/<id>`로 조회할 때 장부를 확인합니다. 다른 장부의 사진 id를 넣으면 404가 나고, 로그인하지 않으면 401이 납니다. 같은 장부에 들어온 사람끼리는 서로 올린 사진이 보입니다.

초대 링크의 토큰은 무작위 24바이트이고, 한 번 쓰거나 기한이 지나면 안 열립니다. 주인이 아니면 만들 수 없습니다.

서버 모드에서는 매물을 브라우저에 캐시하지 않습니다. 한 기기를 여러 사람이 써도 로그아웃하면 남지 않습니다.

## 관리 화면

`ADMIN_EMAIL` 로 지정한 계정으로 로그인하면 **관리** 탭이 하나 더 생깁니다. 다른 사람에게는 탭이 안 보이고, 관리 API 도 404 로 응답합니다. 화면에서 숨기는 게 아니라 서버가 막습니다.

```bash
npx wrangler secret put ADMIN_EMAIL
```

| 할 수 있는 일 | 설명 |
|---|---|
| 회원 보기 | 이메일, 이름, 가입 방식(구글·이메일·둘 다), 연령대, 가입일, 마지막 로그인, 속한 장부 수 |
| 연령대별 통계 | 아래 [연령대와 통계](#연령대와-통계) |
| 잠금 풀기 | 비밀번호를 여러 번 틀려 잠긴 계정을 바로 풀어줍니다 |
| 강제 로그아웃 | 그 회원의 모든 기기 세션을 끊습니다 |
| 회원 삭제 | 계정과 그가 주인인 장부를 함께 지웁니다. 자기 계정은 못 지웁니다 |
| 장부 보기 | 참여 인원, 매물 수, 사진 수와 용량 |
| 장부 삭제 | 매물·사진·설정까지 함께 사라집니다 |
| 백업 내려받기 | 매물과 장부를 JSON 으로 |

지우는 단추는 한 번 더 눌러야 실행됩니다.

## 연령대와 통계

가입할 때 연령대를 한 번 묻습니다. 10대부터 60대까지 여섯 중 하나이고, 안 밝혀도 됩니다. 쓰이는 곳은 딱 하나, 관리 화면의 **연령대별 통계**입니다. 또래끼리 어떤 금액과 넓이의 집을 보는지 견줍니다.

**매물을 처음 넣은 사람의 연령대로 셉니다.** 장부는 여럿이 함께 쓰므로 마지막에 고친 사람으로 세면 남이 한 번 고칠 때마다 주인이 바뀝니다. 연령대를 안 밝힌 사람은 "안 밝힘"으로 따로 셉니다.

**집계용 표는 따로 없습니다.** 매물은 `properties.data`에 JSON 한 덩어리로 들어 있는데, 이걸 복사해 따로 쌓으면 둘이 어긋나기 시작합니다. 대신 생성 컬럼으로 JSON 안의 거래 형태·금액·면적을 비춰만 봅니다(migrations/004). 값을 따로 담지 않으니 용량이 안 늘고, 저장하는 코드는 그대로이고, 이미 들어 있는 매물도 바로 집계됩니다. 집계는 전부 `v_prop_stats` 뷰 하나를 봅니다.

이미 배포된 DB에 나중에 넣으려면 두 마이그레이션을 차례로 실행합니다.

```bash
npx wrangler d1 execute house-hunt --remote --file=migrations/003-google-and-age.sql
npx wrangler d1 execute house-hunt --remote --file=migrations/004-stats.sql
```

## 백업

데이터는 Cloudflare D1 한 곳에 있습니다. 사진도 거기 같이 들어 있습니다. 세 겹으로 받쳐둡니다.

### 1. 되돌리기 — 자동, 30일, Cloudflare 안

D1이 스스로 모든 변경을 기록합니다. 켤 것도 돈 들 것도 없습니다. 실수로 지웠을 때 그 직전으로 되돌립니다.

```bash
npx wrangler d1 time-travel info house-hunt
npx wrangler d1 time-travel restore house-hunt --timestamp=2026-09-14T09:00:00Z
```

### 2. 매일 사본 — 자동, 90일, 계정 밖

`.github/workflows/backup.yml` 이 매일 새벽 4시(한국 시간)에 통째로 내보내고, 크기와 테이블이 멀쩡한지 검사한 뒤, AES-256으로 잠가 Actions 아티팩트로 보관합니다. Cloudflare 계정에 무슨 일이 생겨도 남습니다.

**한 번만 설정하면 됩니다.** 저장소 Settings → Secrets and variables → Actions 에 세 개를 넣으세요.

| 이름 | 어디서 |
|---|---|
| `CLOUDFLARE_API_TOKEN` | Cloudflare 대시보드 → My Profile → API Tokens. D1 읽기 권한이면 충분합니다 |
| `CLOUDFLARE_ACCOUNT_ID` | `npx wrangler whoami` 가 알려줍니다 |
| `BACKUP_PASSPHRASE` | 아무 긴 문자열. **잃어버리면 백업을 열 수 없습니다** |

암호로 잠그기 때문에 저장소가 공개여도 내용이 새지 않습니다. 손으로 돌리려면 Actions 탭에서 Run workflow 를 누르세요.

### 3. 지금 손으로

```bash
./tools/backup.sh                    # ~/Backups/house-hunt 에 저장
./tools/backup.sh ~/Dropbox/backup   # 원하는 곳에
```

내보내서 크기와 테이블을 검사하고 gzip으로 눌러 보관합니다. 최근 30개만 남기고 오래된 것은 지웁니다.

관리 화면의 **데이터 내려받기** 단추를 누르면 매물과 장부만 JSON으로 받습니다. 비밀번호 해시와 사진 본체는 빠집니다.

### 되돌려 넣기

잠긴 파일을 먼저 풉니다.

```bash
openssl enc -d -aes-256-cbc -pbkdf2 -iter 300000 -in house-hunt-20260914.sql.enc -out dump.sql
```

덤프의 `CREATE TABLE` 문에는 대부분 `IF NOT EXISTS` 가 없어서 **빈 데이터베이스에 부어야** 합니다. 지금 데이터베이스를 되돌리는 것이라면 1번 되돌리기가 더 안전합니다.

```bash
npx wrangler d1 execute house-hunt --remote --file=dump.sql
```

실제로 빈 데이터베이스에 부어 회원·장부·매물이 그대로 살아나는 것을 확인했습니다.

## 로컬에서 돌려보기

```bash
npx wrangler d1 execute house-hunt --local --file=schema.sql
printf 'SESSION_SECRET=아무거나\nSIGNUP_CODE=테스트코드\n' > .dev.vars
npx wrangler dev --local
```

`.dev.vars`에 `ALLOW_OPEN=1`을 넣으면 로그인을 건너뜁니다. 배포한 주소에서는 절대 켜지 마세요.

> 지금 이 모드는 장부를 만들어 주지 않아서 API가 모두 500을 냅니다. 화면은 뜨지만 매물이 저장되지 않습니다. 고치기 전까지는 아래 정적 서버를 쓰세요.

화면만 손볼 때는 D1 없이 정적 서버로 띄우는 편이 빠릅니다. 로그인 없이 브라우저 저장으로 돕니다.

```bash
python3 -m http.server 8788
```

네이버 붙여넣기 파서를 고쳤다면 이걸 먼저 돌리세요. 실제 화면에서 복사한 글로 104가지를 확인합니다.

```bash
node tools/test-parse.mjs
```
